# FARA: two-minute judge demo

FARA stands for **Food Access Resource Allocation**.

Start the app with the README commands using JSON development storage or the Firestore Emulator. Use a fresh plan for each take and label survey submissions as demonstration responses. Keep the private creator link out of the recording. For a cloud presentation, deploy and smoke-test the public URL first.

For a 2–3 minute version, open **Methodology** to show **Data & methods**, turn **Show event overlay** off and on to demonstrate the proposed-site layer, and close the check-in from the creator page. Refresh the public page to demonstrate the survey gate. Existing pantry coverage remains unknown; there is no current-network layer. On a phone, use **Areas / Map / Plan** and **View area details** below the map instead of the desktop rails.

Judge questions to answer accurately:

- **What impact did you prove?** None causally. The product produces an auditable plan and a community validation loop; it does not predict attendance or reduction in hunger.
- **Why a centroid/point?** It is an interior tract representative point, not an approved venue or a population-weighted center. The marker can be moved and coordinates edited.
- **What’s on Google Cloud?** The deployable architecture is one Cloud Run image plus Firestore. Report the actual deployment status from `VERIFICATION.md`; local emulator tests are not a live deployment.
- **Where is the AI feature?** There is none. AI assistance was used during software development; runtime scoring is deterministic.
- **What data cannot be uploaded?** All supplied raw data stays local and outside Git/Docker contexts. Only permitted minimized derived assets enter the production image.
